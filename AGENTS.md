# Group B research instructions

Read `docs/guidelines.md`, `docs/topics.md`, `task1/submitted_protocol.pdf`, `STATUS.md` and `task2/CHECKLIST.md` before editing research results. The instructor guideline and submitted Group B protocol govern search, eligibility, and review methods. Preserve the submitted PDF byte-for-byte; explain later amendments separately.

Group B owns its searches, screening, extraction, appraisal, prose and conclusions. Group A data can be imported as explicitly labeled **shared candidate leads**. Do not assign Group B acceptance or PRISMA identification counts to those leads until Group B independently documents their discovery/selection route and decisions. Keep both groups' outputs distinct through original analysis, not cosmetic paraphrasing.

For each real database run, log the exact accepted query, field, collection, filters, date/time and timezone, displayed and exported counts, file and hash, operator, and any export limit. A connection test, public search or an RIS file without these details is not a complete formal run. Keep originals unchanged. Never manufacture a count or substitute a planned query for an executed one.

Record duplicate linkage, two independent screening votes if actually obtained, full-text attempts/reasons, quality scores with evidence anchors, and study-level extraction with page/table/figure locations. Do not invent second reviewers or access to paywalled text. Apply the submitted IC/EC criteria and report deviations with reasons, affected records and any reruns. Reconcile PRISMA only from the logs.

Do not commit VPN credentials, cookies, licensed full-text PDFs, or private access links. The user may provide up to six converted papers already mentioned in conversation; do not demand a large manual download batch. Keep a small, prioritized access request if necessary.

Make changes on a feature branch and open a PR for teammate review. Do not merge a research PR automatically. Update `STATUS.md` and the checklist when a milestone changes.
